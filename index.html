.github/workflows/pr-review.yml
name: pr-review
on:
  pull_request:
    types: [opened, reopened]   # not on every push
 
jobs:
  review:
    uses: org/.github/workflows/review.yml@v2
    with:
      profile: terraform     # infra != app review
      require_ticket: true   # vs. acceptance criteria
    permissions:
      contents: read         # advisory - cannot merge
      pull-requests: write

Agentic PR review platform

Teams adopting AI-assisted coding could suddenly write code far faster than senior engineers could review it. The bottleneck just moved downstream.

  • Automated first-pass review across 30+ repositories and 400+ pull requests, wired in as one reusable CI workflow instead of thirty separate copies.
  • Pulls the ticket's acceptance criteria alongside the diff, so the review catches missing requirements — not just style.
  • Advisory by design: the agent comments, and humans plus deterministic checks still decide what merges.

Shared Kubernetes platform layer

Every team on the cluster needed the same four things — a hostname, TLS, AWS access, and credentials — and each one was solving them by hand, differently.

  • Automated certificate issuance end to end with DNS-01 validation, so renewal stopped being something a person has to remember.
  • Gave every workload its own identity: an IAM role scoped to exactly one secret, and no static AWS keys anywhere in the cluster.
  • Eight workloads moved onto the standardized pattern — two as deep implementations, six as adoption once the pattern existed.

GitOps delivery for a streaming pipeline

A six-component streaming stack was deployed imperatively from CI — so CI held cluster credentials, ordering was guesswork, and a manual change to a live resource silently won.

  • Replaced push-based deploys with pull-based GitOps: the cluster reconciles toward Git, and CI never holds cluster credentials.
  • Dependency order is declared rather than timed — each stage waits on the previous one being genuinely healthy, not on a sleep.
  • Nothing sensitive in the repository; the database pulls its credentials at runtime through workload identity.
